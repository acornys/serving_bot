# 서빙봇 웹 주문 v4 (1013 · 자동 모드 추가)

> **v4 에서 바뀐 것 (10/13)** — v3 에 **자동 모드**를 더함. 바뀐 파일은 `web_order.py` 와 `static/index.html` 두 개. **윈도우 연습 모드에서만 확인 · 실물(ROS)에서는 아직 안 돌려 봄.** 안 되면 `web_v3` 로 되돌리면 됨.
>
> **자동 모드** — 직원 화면 「🎲 자동 모드」 버튼. 손님이 실시간으로 주문했다고 가정하고, 웹 서버가 테이블을 **하나씩 랜덤으로** 골라 보냄
> - 흐름: 다음 테이블 고르기 → 한 곳으로 출발 → 도착 → 바로 다음 테이블 → … (방금 간 테이블은 연달아 안 고름)
> - 도착 후 웹이 일부러 두는 딜레이는 없음 (자동 모드는 테스트용이라 0초)
> - **도착하자마자 출발하려면 매니저도 바꿔야 함** — 매니저는 도착 후 3초(`SERVE_WAIT_SEC`) 동안 새 주문을 안 받기 때문. 아래 「매니저 (자동 모드 0초용)」 판으로 바꾸면 자동 모드를 켤 때 웹이 이 대기를 0초로, 끌 때 3초로 되돌림. **매니저를 안 바꿔도 자동 모드는 됨** (도착 후 3초 뒤에 다음 곳으로 출발)
> - 도착하면 말풍선 「n번 테이블 도착!」 · 버튼에 끝낸 배달 수가 나옴
> - 끄는 법: 같은 버튼을 다시 누름(가던 배달은 끝까지 감) · 🚨 긴급 정지를 누르면 자동 모드도 같이 꺼짐 · 실패가 나오면 저절로 꺼짐
> - 자동 모드 중에는 직접 보내기(테이블 고르기 · 전체 돌기 · 주방 복귀)가 잠김
> - 도착 후 쉬었다 가게 하려면 `web_order.py` 의 `Auto.THINK_SEC`(지금 0초)를 늘림 — 매니저의 「도착 후 10초 주문 없으면 주방 복귀」보다 짧아야 그 자리에서 바로 다음 테이블로 감
> - 아래 실행 방법의 폴더 이름 `web_v3` 은 `web_v4` 로 바꿔 읽기

## 매니저 (자동 모드 0초용) — `매니저_자동모드0초/`

| 파일 | 내용 |
|---|---|
| `robot5_manager.py` | 깃허브 `robot5` 매니저(10/8 판)에 **두 곳만** 고친 것 — 코드에서 `[추가 v4 자동모드]` 검색 |
| `robot5_manager_깃허브원본_1008.py` | 고치기 전 원본 (비교 · 되돌리기용) |

고친 두 곳:

1. `__init__` 에 한 줄 — `self.declare_parameter('serve_wait_sec', SERVE_WAIT_SEC)` (기본값은 그대로 3초)
2. 도착 후 대기에서 고정 값 `SERVE_WAIT_SEC` 대신 그 파라미터를 읽음 — `wait_sec = float(self.get_parameter('serve_wait_sec').value)`

평소 동작(전체 · 단일 · 골라서 모드의 3초 대기)은 그대로. 자동 모드가 켜져 있는 동안만 0초. **지금 쓰는 매니저가 깃허브 판과 다르면 파일을 통째로 바꾸지 말고 위 두 곳만 손으로 고칠 것.**

```bash
cp ~/serving_ws/src/robot5/robot5/robot5_manager.py ~/serving_ws/src/robot5/robot5/robot5_manager.py.bak_1013
```

```bash
cp ~/serving_bot/serving_bot_깃허브/web_v4/매니저_자동모드0초/robot5_manager.py ~/serving_ws/src/robot5/robot5/robot5_manager.py
```

```bash
cd ~/serving_ws && colcon build --packages-select robot5 && source install/setup.bash
```

손으로 대기 시간을 바꿔 볼 때 (매니저가 켜져 있을 때):

```bash
ros2 param set /delivery_manager_node serve_wait_sec 0.0
```

- 자동 모드를 켜면 「최근 기록」에 `매니저의 도착 후 대기를 0초로 바꿈` 또는 `매니저가 대기 시간 바꾸기를 지원하지 않음` 이 뜸 → 어느 매니저가 켜져 있는지 알 수 있음
- 웹 서버를 자동 모드가 켜진 채로 꺼 버리면 매니저에 0초가 남음 → 매니저를 다시 켜거나 위 명령으로 `3.0` 을 넣음

# (v3 설명 그대로) 서빙봇 웹 주문 v3 (1013 · 실시간 위치 · 도착 말풍선 · 주방 선택)

> **v3 에서 바뀐 것 (10/13)** — 바뀐 파일은 `web_order.py` 와 `static/index.html` 두 개. 손님 화면 · 그림은 `web_v2` 와 같음.
> **윈도우 연습 모드에서만 확인 · 실물(ROS)에서는 아직 안 돌려 봄.** 안 되면 `web_v2` 로 되돌리면 됨.
>
> - **실시간 위치** — 맵 위 로봇 그림이 로봇 좌표를 따라 움직임
> - **도착 표시** — 도착하면 로봇 그림이 그 테이블 옆에 붙고, 머리 위에 「3번 테이블 도착!」 말풍선이 뜸
> - **진행 상황** — 매니저 터미널에 찍히는 내용(가는 중 · 도착 · 실패)이 화면 위 카드와 「최근 기록」에 나옴. 기록에는 그 순간의 X · Y 좌표도 같이 적힘
> - **주방(0)도 고를 수 있음** — 예: 1 → 주방 → 3 (`1,0,3` 으로 나감)

폰으로 주문을 보내는 화면. 주문 콘솔(`order`)을 폰 화면으로 바꾼 것 — 같은 글자(`2` · `3,1,4` · `0` · `STOP`)를 같은 토픽 `/delivery_order` 로 보낸다.
**매니저는 깃허브 `robot5` 판 그대로 쓴다. 고칠 것 없음.**

```
주문      폰 → 웹 서버(web_order.py) → /delivery_order → 매니저 → Nav2 → 로봇
위치      TF(map → base_footprint) → 웹 서버 → 폰 화면      (1초에 5번 읽음)
진행 상황  매니저가 찍는 글자(/rosout) → 웹 서버 → 폰 화면
```

## 매니저를 고칠 때 주의

웹 서버는 매니저가 터미널에 찍는 아래 글자를 읽어서 상태를 만든다. **이 글자나 노드 이름(`delivery_manager_node`)을 바꾸면 진행 상황 · 도착 표시가 안 나온다** (주문 보내기와 로봇 그림 이동은 그대로 됨). 바꿨다면 `web_order.py` 의 `LogWatch` 안 `RE_` 세 줄도 같이 고친다.

| 매니저가 찍는 글자 | 웹이 하는 일 |
|---|---|
| `>> 이동 시작 요청: 3번 테이블 (2.90, 1.61)` | 「가는 중」 + 그 자리의 좌표를 기억 |
| `>> 도달 완료: 3번 테이블` | 「도착」 → 로봇 그림을 그 자리에 붙이고 말풍선 |
| `[…] 현재 좌표 -> X: 1.23 m, Y: 0.45 m` | 좌표 (TF 를 못 읽을 때만 씀) |

## 필요한 파일

이 `web_v3` 폴더를 통째로. `web_order.py` 와 `static` 폴더가 같은 자리에 있어야 화면이 뜬다.

| 파일 | 하는 일 | v2 와 비교 |
|---|---|---|
| `web_order.py` | 웹 서버(Flask). 주문을 `/delivery_order` 로 보내고, 로봇 위치 · 매니저 로그를 읽음 | **바뀜** |
| `static/index.html` | 직원(주방) 화면 — 주소 `/` | **바뀜** |
| `static/customer.html` | 손님 화면 — 주소 `/order` | 같음 |
| `static/img/` | 로봇 그림 4장 · 메뉴 그림 6장 | 같음 |

## 실행 방법

**0. 처음 한 번만 — Flask 설치**

```bash
pip install flask
```

**1. `web_v3` 폴더를 `~/serving_ws/web_v3/` 에 복사** (아래 `~/serving_bot` 은 깃허브를 받아 둔 위치로 바꿈 · `~/serving_ws/web/` · `web_v2/` 는 그대로 둠)

```bash
cp -r ~/serving_bot/serving_bot_깃허브/web_v3 ~/serving_ws/web_v3
```

**2. 로봇 쪽을 평소대로 켜기** — 브링업 → Nav2(2D Pose Estimate) → 매니저. 주문 콘솔 `order` 는 안 켜도 됨

**3. 새 터미널에서 웹 서버 켜기** — 첫 줄에 「진짜 로봇 모드」가 나와야 함

```bash
python3 ~/serving_ws/web_v3/web_order.py
```

v1 · v2 · v3 는 같은 포트(5000)를 쓰므로 **하나만** 켠다.

**4. 노트북 IP 확인**

```bash
hostname -I
```

**5. 폰을 노트북과 같은 와이파이(핫스팟)에 연결하고 접속**

- 직원 화면 `http://<노트북 IP>:5000/`
- 손님 화면 `http://<노트북 IP>:5000/order` (`/order?t=3` 처럼 붙이면 3번 테이블로 바로 열림)

**6. 직원 화면에서 테이블을 누르고 「보내기」** → 로봇 출발

## 직원 화면에서 누르는 것 → 나가는 주문

| 누르는 것 | 주문 글자 | 모드 |
|---|---|---|
| 테이블 1개 + 보내기 | `2` | 모드 2 · 단일 |
| 테이블 여러 개(누른 순서) + 보내기 | `3,1,4` | 모드 3 · 골라서 |
| 테이블 사이에 주방(0) + 보내기 | `1,0,3` | 모드 3 · 주방에 들렀다 감 |
| 주방(0)만 + 보내기 / 🏠 주방 복귀 | `0` | 공통 |
| 전체 돌기 | `1,2,3,4,5,6` | 모드 1 · 전체 |
| 🚨 긴급 정지 | `STOP` | 공통 |

## 화면 오른쪽 위 표시

| 표시 | 뜻 |
|---|---|
| 🟢 로봇 연결됨 | 매니저 로그(또는 `/delivery_status`)가 들어오는 중. 깃허브 매니저면 이게 정상 |
| 🟡 연결됨 · 상태 알림 없음 | 매니저는 켜져 있는데 로그가 안 들어옴 → 매니저 창에 1초마다 좌표가 찍히는지 확인. 주문은 나감 |
| 🔴 매니저 꺼짐 | 매니저를 못 찾음 → 매니저가 켜져 있는지 · 같은 와이파이인지 · `ROS_DOMAIN_ID=11` 인지 확인 |
| 연습 모드 · 로봇 없음 | 웹 서버가 ROS 를 못 찾음 → 아래 「안 될 때」 1번 |

## 안 될 때

1. 웹 서버 터미널 첫 줄이 **연습 모드** → 그 터미널에서 `source /opt/ros/humble/setup.bash` · `export ROS_DOMAIN_ID=11` 후 다시 켜기
2. 폰에서 화면이 안 열림 → 폰과 노트북이 같은 와이파이인지 · IP 가 바뀌지 않았는지(`hostname -I` 다시)
3. 화면은 열리는데 로봇이 안 감 → 새 터미널에 아래를 띄우고 폰에서 주문. 글자가 찍히면 웹은 정상(매니저 · Nav2 쪽), 안 찍히면 웹 서버 쪽

```bash
ros2 topic echo /delivery_order
```

4. 주문 콘솔 `order` 로 보내면 가는지 → 가면 로봇 · 매니저는 정상
5. 핫스팟을 바꾸면 노트북 IP 가 바뀜 → `hostname -I` 다시 하고 새 주소로 접속 (코드는 안 고침)
6. 로봇 그림이 안 움직임 → 웹 서버 터미널에 `[알림] 로봇 위치(TF)를 못 읽습니다` 가 찍혔는지 확인. Nav2 에서 2D Pose Estimate 를 해야 위치가 나옴
7. 로봇 그림은 움직이는데 「도착」이 안 뜸 → 위 「매니저를 고칠 때 주의」의 글자가 매니저 창에 그대로 찍히는지 확인
8. v3 가 이상하면 웹 서버를 끄고 `web_v2` 를 켬 (주문 보내기는 v2 와 같음)

## 로봇 없이 화면만 보기 (연습 모드)

```bash
python3 web_order.py --demo
```

- 맥은 5000 포트를 다른 프로그램이 써서 `--port 5050` 을 붙임
- 윈도우는 `py -X utf8 web_order.py --demo` (옵션이 없으면 한글 인코딩 오류로 꺼짐)
- 연습 모드의 가짜 로봇은 맵 그림의 벽을 피해 감. 진짜 로봇은 실제로 간 길의 좌표가 나옴

## 알아 둘 것

- 손님 화면의 주문은 주방 목록에 쌓이기만 하고 로봇은 안 움직임. 로봇은 직원 화면의 「보내기」로만 출발
- 맵 그림은 10/8 배치 구조만 맞는 그림(길이 미측정)이라, 로봇 그림이 벽 · 통로와 조금 어긋나 보일 수 있음. 도착하면 테이블 옆에 붙음
- 자리 좌표는 `web_order.py` 맨 위 `SPOTS_XY`(10/8 깃허브 `robot5` 값). 매니저가 `이동 시작 요청` 을 찍으면 그 좌표로 저절로 바뀜
- 깃허브 매니저일 때는 로봇이 이동 중이어도 웹이 주문을 막지 않음. 이동 중에 보낸 주문은 매니저가 거절함(「최근 기록」에 뜸)
- 주방(0)을 테이블 사이에 넣은 주문(`1,0,3`)은 실물에서 아직 안 보내 봄
- 메뉴 이름 · 값은 `web_order.py` 맨 위 `MENU` 에서 고침. 주문 목록은 서버를 끄면 사라짐
